# DDS V2 真实项目介入、数据接入与报告体系

## 现行产品契约

Input 1/2/3 是三种平行的项目介入方式：

| 方式 | 用户问题 | DDS 角色 | 内容路由 |
|---|---|---|---|
| Input 1 · 独立研判 | 场地存在什么机会、可能走向何处 | 主动研究者与策略提出者 | 机会—客群—方向—标准化压力测试—验证 |
| Input 2 · 约束协同 | 已有约束下哪条路线更优 | 条件解析者与联合策划者 | 条件—矛盾—约束方案—产品操盘—实施闸门 |
| Input 3 · 方案审查 | 多个方案中选谁、淘汰谁、如何优化 | 独立评审者与方案优化者 | 基线—比选—价值风险—推荐淘汰—优化切换 |

系统只生成 `recommended_mode` 和理由。用户确认后冻结 `selected_mode`、原始目标、使用场景、问题、资料、权重、禁止结论和确认时间。未确认不得运行；资料不足只产生 `missing_inputs` 和模块级 `data_readiness`，不得自动切换介入方式。

## 真实资料进入 V2

```text
V1 原始资料（只读）
→ 文件盘点与 SHA-256
→ ProjectManifest / SourceAsset
→ 页码、幻灯片、单元格、图片或时间码定位
→ 来源角色和允许用途校验
→ qualified / needs_review / conflict / rejected
→ V2 冻结快照
```

V2 正式运行不长期读取 V1 路径。DWG 无可靠精确解析时只登记原文件并要求 PDF/DXF；PDF、图片和视频未完成 OCR、转写或人工复核前保持待复核。法定文件、甲方资料、成交、挂牌媒体、客研、案例库和模型各自只能支持被授权的决策字段；LLM 不创造事实。

## 双层输出

客户决策报告只呈现有证据支持、会影响当前决定的内容。每页必须有具体问题、真正结论、主要证据或设计表达、决策影响或行动；普通缺口不占正文页，只有阻断当前决定的缺口可成为“决策闸门”。

内部证据工作包保留全量资料、提取定位、来源准入、候选主张、冲突、缺口、模型参数、冻结哈希和 QA。程序字段、原始来源 ID 和模型哈希不得挤占客户正文。

## 深圳高层验收基线

深圳宝安 A002-0113 项目是首个真实迁移样本。原始 PPTX、招标法定资料、证据备忘和设计资料必须进入正式来源登记；原 V1 十二页只作为业务内容基线，经页面价值门后生成 Input 3 决策报告，并单独生成证据工作包。报告不得含合成测试数据、空页、英文 schema、固定 0% 置信度或被截断宽表。

最终验收包括：模式确认契约、来源与哈希回溯、全量自动化测试、1280×720 / 1440×900 / 1920×1080 浏览器检查，以及打印 PDF 检查。
